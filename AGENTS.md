# Правила проекта Silo

## Комментарии

1. Комментарий описывает функцию - что делает код. А не то, что мы сделали
   на данный момент. Истории изменений в комментариях быть не должно:
   никаких «добавили», «поправили», «переделали», «раньше было так»,
   «теперь работает иначе».

2. Коротко. Обычно достаточно одной строки. Больше - только если без этого
   смысл действительно непонятен.

3. Не пересказывай очевидное из кода. Если по самому коду всё ясно,
   комментарий не нужен.

4. Если что-то сложное - не расписывай это в комментарии, а напиши
   объяснение в чат отдельным сообщением.

5. Тире только короткое: "-". Длинное тире "—" не использовать.
   Это правило касается всего текста, а не только комментариев.

6. Касается любого кода в проекте: Go, JS, CSS, HTML.

Исключение: тестовый плагин. Там комментарии подробные, потому что он
служит примером для разработчиков.

Комментарии на русском языке.

## Логирование

1. Каждое сообщение начинается с тега в квадратных скобках: "[Web] ...".
   Тег - одно слово, которое указывает, к чему относится лог: модуль,
   подсистема или область. Примеры: "[App]", "[Web]", "[Config]",
   "[Plugin]", "[Torrent]", "[User]", "[Catalog]".

2. Тег пишется в начале сообщения, отдельного аргумента для него нет.
   Пробелы внутри тега допустимы только когда одного слова мало:
   "[Torrent Manager]", "[Torrent Engine]".

3. Постоянный тег для модуля: одно и то же место всегда пишет один и тот
   же тег. Свой вариант тега для одного и того же модуля не придумывать.

4. Если сообщение относится к конкретному объекту, тег уточняется через
   двоеточие без пробела: "[Plugin:tester]", "[User:admin]". Уточнение -
   это ID, имя или логин, а не произвольный текст.

5. Уровень выбирается по смыслу:
   - Debug - подробности для разработки, которых нет в обычном режиме;
   - Info - обычные значимые события: старт, остановка, успешная операция;
   - Warn - неожиданное, но не ломающее работу: отказ, пропуск, дефолт;
   - Error - операция не выполнена, нужна реакция.

6. Сообщения на английском языке. Текст - с заглавной буквы, без точки
   в конце. Тег всегда латиницей.

7. Сообщение описывает событие, а не адрес в коде: не "in function
   loadConfig", а "failed to load config".

8. Значения передаются параметрами и форматированием ("%s", "%v"),
   а не склейкой строк. Ошибку добавлять в конец: "...: %v".

9. Формат строки задает логгер, а не вызывающий код: время, уровень и
   стек добавляются автоматически, дублировать их в сообщении не нужно.

10. Сообщение не должно содержать секретов: паролей, токенов, ключей.

## Интерфейс

1. Панель целиком перерисовывается только при входе в раздел. Всё, что
   обновляется по таймеру или по событию, обновляется точечно - отдельным
   компонентом, а не всей панелью.

2. Причина: перерисовка панели стирает ввод, сбрасывает фокус и позицию
   курсора, сбрасывает выделение. Пользователь теряет то, что печатал.

3. Для точечного обновления используется общий модуль `/js/ui.js`
   (`siloUI.render`, `siloUI.text`, `siloUI.on`, `siloUI.timer`,
   `siloUI.stopAll`). Свой велосипед для каждой панели не пишем.

4. Каркас раздела строится один раз. У изменяемых узлов должны быть
   постоянные `id`, и обновляется содержимое именно этих узлов.

5. Обработчики вешаются через делегирование на корневой узел раздела
   (`siloUI.on`). Корневой узел создаётся заново при каждой отрисовке,
   поэтому подписки не накапливаются.

6. Периодические обновления запускаются через `siloUI.timer` с ключом
   раздела, при смене раздела вызывается `siloUI.stopAll()`. Прямой
   `setInterval` без пары `clearInterval` оставляет утечку: таймер
   предыдущего раздела продолжает работать и обновлять несуществующие узлы.

7. Правило касается и админки, и основного интерфейса, и плагинов.

8. Списки и таблицы обновляются построчно через `siloUI.rows`: строка с
   неизменившимся содержимым переиспользуется. Перерисовка всей таблицы
   через `innerHTML` сбрасывает фокус с кнопок и выделение.

9. Ввод спрашивается модальными окнами админки (`showModal`,
   `modalConfirm`, `modalAlert`), а не `alert`, `confirm` и `prompt`.
   Встроенные окна браузера выбиваются из оформления и не дают
   проверить введённое до закрытия.

10. Несколько полей в одном окне собираются через `getValue`: при ошибке
    возвращается `undefined`, окно остаётся открытым, а текст подсказки
    показывается рядом с полями.

11. Общие элементы интерфейса берутся из общего стиля `/css/style.css`:
    панели, кнопки, поля, таблицы, карточки показателей, бейджи,
    модальные окна. Свой стиль плагина дополняет общий, а не повторяет его.

12. Классы общих элементов: `.panel`, `.btn`, `.btn-secondary`,
    `.btn-danger`, `.btn-sm`, `.input`, `.field`, `.row`, `.hint`,
    `.table-wrap`, `.table`, `.actions-cell`, `.cards`, `.stat-card`,
    `.badge` и его варианты, `.modal-overlay`. Прежде чем писать новый
    стиль, проверь, нет ли подходящего среди общих.
