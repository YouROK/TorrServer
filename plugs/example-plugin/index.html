All Silo plugin APIs, documented and interactive

1. ts.info - System Information

Read-only object with system data. Available in service.js immediately on startup. Use for logging, feature detection, or displaying version info to users.

Contains version, OS, CPU count, and the plugin's own ID. Values are populated by the core before service.js executes. 
// In service.js:
console.log(ts.info.version);         // "1.2.3"
console.log(ts.info.plugin_id);       // "example-plugin"
console.log(ts.info.os);              // "linux"
console.log(ts.info.arch);            // "amd64"
console.log(ts.info.num_cpu);         // 4
console.log(ts.info.torrent_version);

2. ts.web - Web Routes & Static Files

Register HTTP endpoints and serve static files. Every route must be whitelisted in info.yaml routes[]. If not listed, request is silently dropped. Supported methods: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS, PROPFIND. Also any() for all methods and route(method, path, fn).

URL Prefix Rule:

All plugin routes live under /plugins/<plugin_id>/. Example: registering ts.web.staticDir("/css", "css") makes files available at /plugins/example-plugin/css/. In HTML and JS files use relative paths (e.g. css/style.css, js/app.js). Never use absolute root paths like /css/style.css, they resolve to the server root, not the plugin.

Request object (first arg):
  • req.method - HTTP method string
  • req.path - URL path
  • req.query - parsed query params as object
  • req.headers - lowercase header names as keys
  • req.body - parsed body: JSON object, form object, or raw string
  • req.user - authenticated user object or null
Response (return value or second arg):
  • return obj - auto JSON
  • return "string" - text/plain
  • res.status(200).json({}) - explicit JSON
  • res.text("hello") - text/plain
  • res.html("<b>bold</b>") - text/html
  • res.stream(handle, name) - file stream (from ts.torrfs.open)
  • res.end() - no body, only headers (HEAD)
Static routes and i18n:

You do not need to register /i18n/* or call staticDir("/i18n", ...). The core reads your i18n/*.json files from the plugin VFS automatically at load time and merges them into the global /i18n.js.

// Static files (VFS path to URL mapping)
ts.web.staticFile("/", "index.html");
ts.web.staticDir("/css", "css");
ts.web.staticDir("/js", "js");

// API endpoints
ts.web.get("/api/hello", function(req) {
    return { message: "Hello", user: req.user };
});

ts.web.post("/api/echo", function(req) {
    return res.status(201).json({ you_sent: req.body });
});

// Custom method
ts.web.route("PROPFIND", "/api/dav/*path", function(req, res) {
    res.status(207).header("Content-Type", "application/xml").text("...");
});

3. ts.bus - Event Bus

Publish/subscribe messaging. Plugins communicate via named topics. Topics must be declared in info.yaml events[]. Own plugin topics (plugin:<id>:*) are always allowed.

Topic naming convention:
  • system:* - Core lifecycle: system:boot, system:shutdown
  • torrent:* - Torrent engine events
  • plugin:<id>:<name> - Plugin-scoped events
var unsub = ts.bus.on("system:boot", function(payload) {
    console.log("Silo started!");
});

ts.bus.emit("plugin:example-plugin:message", { text: "Hello!" });
ts.bus.emit("torrent:added", { hash: "abc...", title: "My Torrent" });

4. ts.storage - Persistent Key-Value Storage

BoltDB-backed key-value store. Keys are prefixed with <plugin_id>: so plugins never collide. Strings only, use JSON.stringify/parse for objects. Persists across restarts.

var value = ts.storage.get("my_key");           // string or undefined
ts.storage.set("my_key", "some string value");
ts.storage.rem("my_key");
ts.storage.clear();

ts.storage.set("config", JSON.stringify({ mode: "append" }));
var cfg = JSON.parse(ts.storage.get("config"));

5. ts.http - HTTP Client

Make outbound HTTP requests. Both GET and POST supported. Useful for fetching metadata, third-party APIs, or connectivity checks. SSRF protection is handled by the core.

var resp = ts.http.get("https://api.example.com/data", {
    headers: { "Authorization": "Bearer ..." },
    timeout: 5000
});
// resp.status, resp.ok, resp.body, resp.json()

var resp2 = ts.http.post("https://api.example.com/submit",
    { action: "test", value: 123 },
    { timeout: 5000 }
);

6. ts.torrent - Torrent Management

Full torrent lifecycle: add, list, get status, remove. Works with magnets or info hashes. All operations are scoped to a user (default: "owner").

var list = ts.torrent.list();
var status = ts.torrent.add("magnet:?xt=urn:btih:...", {
    title: "My Torrent",
    category: "movies"
});
var info = ts.torrent.get("abc123hash...");
ts.torrent.remove("abc123hash...");

7. ts.users - User Management

Read-only access to the user list. Returns user objects with id, username, rank (0=guest, 10=user, 50=admin, 100=owner), is_banned, created_at.

var users = ts.users.list();
var user = ts.users.get("owner");

8. ts.i18n - Internationalization

Plugins can add translations via static i18n/<lang>.json files (loaded automatically) AND programmatically via ts.i18n.add/addMany in service.js.

ts.i18n.lang("de", "Deutsch");
ts.i18n.add("en", "my_key", "English string");
ts.i18n.addMany("en", { "key1": "Value 1", "key2": "Value 2" });

9. ts.crypto - Hashing, Encryption, Random

Cryptographic primitives for hashing, key derivation, symmetric encryption, random bytes, and safe comparison of secrets. All functions are synchronous and return strings (hex or base64) for convenient use in JavaScript.

Why strings, not byte arrays?

JS does not have a native byte type. Uint8Array exists but working with it is awkward. Strings are universal: hash outputs can be stored in JSON, compared with ===, sent over HTTP.

When to use what:
  • sha256 - checksums, content IDs, cache keys
  • hmacSha256 - verify webhooks (GitHub, GitLab, Telegram)
  • pbkdf2 - derive key from password with salt
  • bcrypt - store user passwords (self-salting)
  • aesGcm - encrypt secrets at rest in ts.storage
  • constantTimeCompare - compare tokens/hashes without timing leak
ts.crypto.sha256("hello");                    // 64 hex chars
ts.crypto.sha1("hello");                      // 40 hex chars
ts.crypto.md5("hello");                       // 32 hex chars
ts.crypto.hmacSha256("secret-key", "data");

var salt = ts.crypto.randomBytes(16);
var hash = ts.crypto.pbkdf2("password", salt, 100000, 32);

var h = ts.crypto.bcrypt("secret");
ts.crypto.bcryptVerify("secret", h);          // true

ts.crypto.randomBytes(16);
ts.crypto.randomBase64(16);
ts.crypto.uuid();

ts.crypto.base64encode("text");
ts.crypto.hexEncode("text");

var ct = ts.crypto.aesGcmEncrypt("my-key", "secret message");
var pt = ts.crypto.aesGcmDecrypt("my-key", ct);

ts.crypto.constantTimeCompare(token1, token2);

10. ts.torrfs - Torrent Virtual Filesystem

Read-only virtual filesystem over the user torrent library. Provides a filesystem tree (categories, torrents, nested folders, files) built from the database. Individual files can be opened as handles and streamed through res.stream.

Why a filesystem, not just torrent list?

ts.torrent gives you torrents as flat objects. Real clients (WebDAV, FUSE, SFTP) expect a hierarchy: folders, files, paths. ts.torrfs builds that hierarchy from the database.

Database-driven, engine is lazy:

The whole tree is built from bbolt. The torrent engine is not touched during list/stat, sleeping torrents stay asleep. Only ts.torrfs.open wakes the engine and creates a reader.

Handles and streaming:

A handle is an opaque object representing an open reader. Pass it to res.stream and the core runs http.ServeContent outside the JS mutex. The handle is closed automatically after the response finishes.

var nodes = ts.torrfs.list(userID, "");
// [
//   { name: "Movies", path: "Movies", is_dir: true, size: 0, mtime: 1234567890 },
//   ...
// ]

var files = ts.torrfs.list(userID, "Movies/Inception");
// [
//   { name: "film.mkv", path: "Movies/Inception/film.mkv",
//     is_dir: false, size: 5368709120, mtime: 1234567890,
//     mime: "video/x-matroska" },
//   ...
// ]

var node = ts.torrfs.stat(userID, "Movies/Inception/film.mkv");

var h = ts.torrfs.open(userID, "Movies/Inception/film.mkv");
res.header("Content-Type", node.mime);
res.stream(h, "film.mkv");

11. info.yaml - Manifest Reference

Every plugin has an info.yaml. Think of it as a contract: fields you declare grant permission to use those APIs. Undeclared routes or events are silently denied at runtime.

Field Type Required Description Example
id string yes Unique identifier. URL prefix, VFS namespace, storage prefix. Lowercase, no spaces. "my-plugin"
name string yes Human-readable name for admin UI and plugin lists. "My Plugin"
version string recommended Semantic version shown in admin panel. "1.0.0"
author string optional Author credit shown in admin panel. "John Doe"
description string optional Short description for plugin list. "Does X and Y"
entry string recommended Path to main JS file. Executed once on startup. "service.js"
theme_ui bool optional If true, plugin REPLACES the root page at /. Only one plugin can be theme. true
icon string optional Path to icon inside plugin's VFS. Shown in admin plugin list. "/img/icon.png"
menu[] array optional Sidebar navigation entries. Each: title, route, rank, icon. User sees only where user.rank >= entry.rank. - title: "Page"
route: "/"
rank: 0
events[] array of strings recommended Whitelist of bus topics. Use "topic:*" for wildcard. Unlisted: permission denied. - "system:boot"
- "torrent:*"
routes[] array of strings recommended Whitelist of URL paths. Use "/path/*" for prefix matching. Unlisted: silently dropped. - "/api/*"
- "/static/*"
